# Nexo — Non-Negotiable Rules for Aider

This file is loaded as read-only context in every session (see `.aider.conf.yml`). Do not edit this file yourself, Aider; ask Piñá to update it if a rule changes.

## Language
- All code, comments, docstrings, variable/class names, and commit messages: in **English**.
- Conversational chat responses to Piñá in Aider: in **Spanish**.

## Architecture (Strict Clean Architecture)
- Domain (`lib/domain/`): Pure Dart. ZERO Flutter dependencies, ZERO imports from `data/` or `presentation/`.
- Data (`lib/data/`): Implements interfaces from `domain/repositories/`. Never the reverse.
- Presentation (`lib/presentation/`): Riverpod (`Notifier`, `AsyncNotifier`, `FutureProvider`, `StreamProvider`). Never `StateNotifier` (deprecated). Never import repositories or database directly — always go through a `UseCase`.
- Every repository and use case returns `Result<T, Failure>` (`lib/core/utils/result.dart`). Throwing exceptions or using `try-catch` to bubble business errors up across these layers is strictly forbidden.

## Database (Drift)
- Never edit `*.g.dart` files manually — they are generated.
- If you change a table or `TypeConverter`, state it explicitly and remember to run:
  `dart run build_runner build --delete-conflicting-outputs`
- All schema migrations must go into `MigrationStrategy.onUpgrade` in `app_database.dart`, incrementing `schemaVersion`. Never modify an existing, already-released `if (from < N)` migration block — always add a new one.

## Audio Engine (`NexoAudioHandler`)
- Never unify `_playerA`/`_playerB` into a single player. The double-buffer architecture is intentional for gapless playback and crossfade transitions.
- Never call `.stop()` on the active playing player that sustains the visible foreground service during a transition — it breaks the double-buffer pattern and causes notification flicker (see bug 2.1).
- Live configuration changes (crossfade, performance profile) must be applied via live setters called from `ref.listen`, never read only once at startup.

## UI / Performance (Target Hardware: Helio G85 2GB RAM / Pentium E5800 4GB RAM)
- `BackdropFilter` and glassmorphism are forbidden. Use Soft UI / M3 Expressive (`BoxShadow`, `surfaceContainerHighest`).
- Lists with 15,000+ items: always use `ListView.builder`/`GridView.builder` with fixed `itemExtent`.
- `CustomPainter` is only permitted for single, non-repeated visualizations with correct `shouldRepaint` (e.g. `_EqCurvePainter`). Never inside repeated list/grid items.
- If wrapping a `ListTile`/`InkWell` in a `Container` with custom `BoxDecoration`, wrap it in `Material(type: MaterialType.transparency)` to avoid masking the ink ripple.

## Code Delivery
- Full file replacements, ready to copy-paste. Never placeholders like `// rest of code unchanged`.
- Always verify that the proposed code satisfies `flutter analyze` with zero issues.
- Every commit increments the build number (`+N`) in `pubspec.yaml` monotonically. Semantic version (`0.0.X-beta`) only increments upon completing a full sprint.

## What to do when in doubt
Ask before assuming. A short pause is always better than a fix that violates any of the above rules.
